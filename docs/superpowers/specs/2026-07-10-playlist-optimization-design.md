# 播放列表功能优化设计文档

## 概述

本文档描述音乐播放器播放列表功能的三项核心优化：歌曲时长显示修复、添加有效歌曲功能优化、搜索功能综合优化。

## 需求背景

### 问题描述
1. **歌曲时长显示异常**：播放列表中所有歌曲均显示为"00:00"，无法看到实际时长
2. **添加歌曲缺乏验证**：可以添加无效、损坏或格式不支持的音频文件
3. **搜索功能需要优化**：准确性、响应速度和用户体验有待提升

### 用户需求
- 时长格式：MM:SS（固定两位），如 `03:45`、`00:58`
- 歌曲验证：全面验证（playable+URL+duration）+ 实时验证（HEAD请求）
- 搜索优化：准确性、速度、展示全面优化

## 设计方案

### 任务1：歌曲时长显示修复

#### 问题根因
- `shared/types.ts` 中的 `Track` 接口缺少 `duration` 字段定义
- `web/src/data/tracks.ts` 在映射时未包含 `duration` 字段
- 虽然 `tracks.json` 中有 `duration` 数据（毫秒单位），但未传递到前端

#### 解决方案
1. **修改 `shared/types.ts`**
   - 在 `Track` 接口中添加 `duration?: number` 字段

2. **修改 `web/src/data/tracks.ts`**
   - 在映射函数中添加 `duration: t.duration`

3. **保持现有实现**
   - `PlaylistManager.tsx` 中的 `formatDuration` 函数已正确实现 MM:SS 格式

#### 数据流
```
tracks.json (duration: 319039)
  ↓ 映射
Track 对象 (duration: 319039)
  ↓ formatDuration
显示 "05:19"
```

### 任务2：添加有效歌曲功能优化

#### 多层验证流程
```
用户点击添加歌曲
  ↓
第一层：本地验证
  - playable === true
  - audioUrl 非空且非 example.com
  - duration > 0
  ↓ 失败 → 显示错误提示"歌曲信息不完整"
第二层：实时验证
  - HEAD 请求检查 audioUrl 可访问性
  - 检查 Content-Length > 1MB（排除45秒预览）
  ↓ 失败 → 显示错误提示"歌曲音频不可用"
添加成功 → 显示成功提示
```

#### 错误处理
- 网络超时：显示"网络超时，请稍后重试"
- URL失效：显示"歌曲音频链接已失效"
- 已存在：显示"歌曲已在播放列表中"

#### 实现细节
1. **创建验证函数 `validateTrack`**
   - 输入：Track 对象
   - 输出：{ valid: boolean, error?: string }

2. **创建实时验证函数 `verifyAudioUrl`**
   - 输入：audioUrl 字符串
   - 输出：Promise<{ accessible: boolean, size?: number }>

3. **修改添加歌曲逻辑**
   - 在 `addTrackToPlaylist` 前调用验证
   - 显示验证状态和结果

### 任务3：搜索功能综合优化

#### 准确性优化
1. **拼音匹配**
   - 实现拼音转换函数
   - 支持首字母匹配（如 "zjl" 匹配 "周杰伦"）
   - 支持全拼匹配（如 "zhoujielun" 匹配 "周杰伦"）

2. **模糊匹配**
   - 支持部分匹配（如 "晴天" 匹配 "晴天(DJ版)"）
   - 忽略大小写
   - 忽略特殊字符

3. **相关性排序**
   - 完全匹配 > 开头匹配 > 包含匹配
   - 标题匹配 > 艺术家匹配

#### 响应速度优化
1. **缓存优化**
   - 缓存容量：50 → 100条
   - 缓存有效期：5分钟 → 10分钟

2. **防抖优化**
   - 防抖延迟：300ms → 200ms

3. **请求优化**
   - 保持现有重试机制
   - 优化请求取消逻辑

#### 结果展示优化
1. **显示更多信息**
   - 歌曲封面缩略图
   - 歌曲时长
   - 专辑名称

2. **关键词高亮**
   - 匹配的关键词加粗显示
   - 支持多关键词高亮

3. **交互优化**
   - 点击歌曲直接播放
   - 长按显示操作菜单

## 性能指标

1. **时长显示**：加载时即时显示，无延迟
2. **添加歌曲验证**：本地验证 < 10ms，实时验证 < 2s
3. **搜索响应**：本地搜索 < 50ms，在线搜索 < 3s

## 风险评估

1. **拼音库体积**：可能增加打包体积
   - 缓解方案：使用轻量级拼音库或自定义实现

2. **实时验证延迟**：HEAD请求可能增加添加歌曲时间
   - 缓解方案：显示加载状态，支持取消操作

3. **缓存一致性**：缓存可能导致搜索结果不最新
   - 缓解方案：提供手动刷新按钮
